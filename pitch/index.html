The problem

Assumptions move after the feasibility is approved. The model doesn't.

Commercial projects rest on assumptions about construction costs, financing, timelines, rents and exit values. When those assumptions change, profitability changes too, but the pro forma is usually rebuilt by hand, weeks later, after more capital is committed.

Current state

Today, finding the hit takes a manual rebuild.

Developers typically rely on an in-house Excel pro forma, plus periodic reports from a cost consultant or quantity surveyor. Each covers part of the picture; none connects a price change to the return.

Today

  1. Excel pro forma built once at Day 0, owned by one analyst
  2. QS or cost consultant reports cost-to-date monthly or quarterly as a PDF
  3. Analyst re-keys actuals into a variance sheet
  4. Team searches emails and change orders to explain each overrun
  5. Pro forma rebuilt by hand to see the new return
  6. Decision made on numbers that are already weeks old

Why it falls short

  • Excel models are static and break when someone else edits them
  • QS reports measure cost, not the impact on IRR
  • Weeks pass between a price rise and a rebuilt model

With SiteSense

  1. Upload the model once; AI extracts assumptions, code checks the totals
  2. Milestone actuals and price changes flow in
  3. Code recomputes variance, schedule slip and IRR in seconds
  4. AI drafts the driver of each variance, citing the source line
  5. You approve or edit every driver
  6. Re-forecast with a go, hold or re-scope flag. The decision stays yours

Earlier warnings

See the IRR move when prices move, not at the quarterly review.

Fewer bad commitments

Stress-test the deal before signing the land or the next draw.

How it works

AI reads the messy text. Code does the math. You make the call.

AI only handles unstructured inputs. Every number is computed by code, and the developer approves every explanation before it counts.

StepHandled byWhy
Extract assumptionsAI CodeEvery developer's model has different layouts and labels, so fixed cell mappings break. Code then checks extracted totals against the source.
Ingest actualsCodeFixed connectors are deterministic and cheap; AI adds nothing here.
Variance and IRRCodeArithmetic must be exact and repeatable. A language model never calculates the numbers.
Explain driversAICauses live in free text such as change orders, emails and site notes. Keyword rules can't link a rebar rate revision to a budget-line overrun.
Review and approveYouThe developer is accountable; AI explanations are drafts until confirmed.
Re-forecastCode AIA formula produces the numbers; AI only writes the plain-language summary. The go, hold or re-scope call stays with you.

GitHub holds the prompts, extraction schema, sample project and test cases, and deploys to Vercel on push.

Misread assumption

AI picks up hard costs instead of total costs. The checksum against the source model must pass before anything runs.

Wrong driver blamed

An overrun tagged as a price rise was really a scope change. You approve every driver before it counts.

Stale actuals

An old cost report hides an overrun. Each source shows its last-updated date, and anything past cadence is flagged.
